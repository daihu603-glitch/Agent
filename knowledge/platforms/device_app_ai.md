# 设备 + APP + AI 端到端产品

## 统一契约
- 统一设备 ID、用户/租户、会话、协议版本、消息 schema、命令 ID、幂等键、错误码、超时和三端追踪 ID。
- 建立固件、APP、后端和模型/提示词的兼容矩阵；测试版本过高、过低和字段缺失时的拒绝或降级行为。
- 三端构建产物必须来自同一需求基线并绑定各自源码修订，禁止拿旧固件、旧 APK 或历史 AI 评测拼成“本次通过”。

## 控制安全
- AI 只生成结构化候选命令，不直接获得烧录、SSH、执行器或生产部署权限。
- 后端负责身份、资源范围、参数约束、限流和人工确认；APP 显示动作与对象；固件独立执行速度、角度、温度、电流等最后安全限位。
- 断网、模型不可用、重复/重放命令、确认超时和状态不明时必须进入已定义安全状态；不能因云端恢复而自动重复危险动作。
- OTA、烧录和恢复出厂不属于普通聊天工具，分别设置确认和版本/签名校验；不可逆安全熔断不自动执行。

## 联调与验收
- 正常链路验证设备绑定、APP 操作、AI 建议、用户确认、设备执行和状态回传，并用命令 ID 对齐三端日志。
- 异常矩阵覆盖 BLE/Wi-Fi 断连、后端重启、模型超时、无效工具、越权、提示注入、重复请求、APP 杀进程、固件复位和升级回滚。
- 长稳同时记录设备错误/复位、APP 崩溃/ANR、后端时延/错误率、内存/句柄和 Token 成本；单端 version 循环不能替代业务压力。
- 统一需求门禁要求每条需求设计、代码、测试和真实证据完整；任一端 not_run/fail/blocked 均阻止正式交付。
