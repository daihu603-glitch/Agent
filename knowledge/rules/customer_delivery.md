# 客户需求、验收与交付规则

## 需求基线
每条需求必须有：唯一 ID、客户原始描述/来源、可测量验收标准、验证方法、优先级、设计/代码/测试追踪。
- FR：功能；NFR：性能/可靠性/资源；IF：硬件/软件接口；SAFE：安全/升级/恢复；CR：后续变更。
- 不接受“运行稳定”“速度快”这类不可验收表述。转换为例如“25±2°C、额定负载连续 24h，无复位/死锁，错误率≤...”。
- 未确认项写 assumption/open_question，不能默认为客户承诺。需求变更要更新基线版本并重新评估影响。

## 验证层级
代码审查/静态检查 → 编译 → 单元/仿真 → 台架 → HIL → 异常/压力/长稳 → 客户场景验收。
验证方法：inspection（审查）、analysis（计算分析）、bench_test、hil_test、stress_test、customer_test。

## 证据
每条 pass 必须绑定：需求 ID、软硬件版本、Git SHA、设备序列号（如有）、环境、步骤、原始日志、结果、测试者、时间。
截图/摘要不能替代原始日志；fail/blocked/not_run 不得改成 pass。waived 需要客户书面批准，不应作为自动正式交付通过项。

## 发布门禁
1. 所有需求设计/代码/测试追踪完整，全部 pass 且有证据。
2. 构建可复现，产物版本与验收版本一致，Git 工作区状态已记录。
3. 无 blocker/critical 缺陷；已知限制和规避措施经客户确认。
4. 交付物含固件/应用、源码或补丁、配置、构建/部署/升级/恢复说明、接口文档、验收报告、第三方许可证。
5. ZIP 内 manifest 和逐文件 SHA256，外部 ZIP SHA256；交付包通过独立校验。
6. 内部调试包可 allow_incomplete，但 manifest 必须标记 WAIVED_INTERNAL_ONLY，不得称为正式客户交付。
