# Android 设备互联 APP 开发与交付

## 需求与架构
- 固定 minSdk/targetSdk、支持机型、BLE/Wi-Fi/TCP/MQTT 协议版本、设备绑定方式、后台行为和验收指标。
- UI、领域状态机、设备连接、持久化和网络层分离；连接状态必须可观察，命令带 ID、超时、重试和幂等语义。
- 协议处理 MTU/分包、通知乱序、重复包、半包、CRC/长度、版本不兼容和时钟偏差；所有外部数据按不可信输入校验。
- 本地数据库迁移、缓存上限、敏感数据加密和删除策略需测试；日志不包含 Wi-Fi 密码、令牌、客户隐私或完整设备数据。

## Android 权限与互联
- Android 12+ 按实际能力申请 BLUETOOTH_SCAN/BLUETOOTH_CONNECT 运行时权限；旧版本定位权限和“不推导位置”声明按真实扫描用途处理。
- 权限拒绝、仅本次允许、蓝牙/定位关闭、后台限制和厂商省电策略都要有可恢复路径，不诱导授予无关权限。
- BLE 处理扫描去重、GATT 回调线程、连接/发现服务/通知顺序、MTU 协商、断线重连和资源关闭；不能在 UI 线程阻塞等待。
- Wi-Fi 配网秘密不得写日志；TCP/MQTT 使用 TLS 和正确主机名/证书校验，禁止 TrustAll、ALLOW_ALL_HOSTNAME_VERIFIER 或随意关闭校验。
- OTA 绑定设备型号、硬件版本、当前/目标版本和签名；验证下载中断、校验失败、掉电、重复升级、回滚与防降级要求。

## 构建与发布
- 标准工程优先 Gradle Wrapper；自定义 build.ps1 必须固定 SDK/JDK/Build Tools 并记录环境。assemble 成功不等于 Lint、单测或仪器测试通过。
- APK 用 apksigner 验证签名和包信息，AAB 用 jarsigner/发布流程验证；保存 SHA256、versionCode/versionName、源码修订和符号/混淆映射。
- 测试签名与生产签名分开，生产 keystore/密码由负责人保管，不进入源码、工作流日志或交付 ZIP。
- 模型 API Key 只能由 AI 后端持有；APK 使用自身用户认证和短期会话，不能通过 Base64、混淆或 Native 库“隐藏”长期模型密钥。

## 真机验收与证据
- 至少覆盖权限拒绝、后台切换、杀进程、断网、断连、设备重启、后端超时、重复命令和低电量场景；仪器测试明确设备 serial。
- logcat 与固件/后端日志通过命令 ID 或追踪 ID 对齐，记录 APP 版本、设备型号、Android 版本和固件版本。
- 交付包含已验证 APK/AAB、构建与签名说明、协议、权限/隐私说明、测试报告、升级回滚手册；不包含私钥、.env、local.properties 或客户数据。
