# STM32 产品开发与交付

## 全流程基线
1. 冻结原理图版本、BOM、芯片完整型号、封装、供电、外部晶振、下载接口与客户验收环境。
2. 保存 CubeMX `.ioc`、HAL/LL/CMSIS 版本、链接脚本、启动文件、编译选项和固件版本。
3. 建立外设接口表：引脚、复用、方向、电平、上下拉、速率、DMA、中断优先级、并发约束。
4. 驱动分层：BSP（板级）→ 外设驱动 → 服务 → 应用。中断只做必要处理，耗时任务移交主循环/RTOS。
5. 构建后归档 `.elf/.map/.hex/.bin`，记录 Git SHA、固件版本、构建时间和配置哈希。
6. HIL 测试必须核验设备版本，覆盖正常、边界、错误注入、断线重连、看门狗、掉电恢复和长稳。
7. 交付包含固件、源码/构建说明、接口协议、引脚/硬件基线、测试报告、已知限制和升级/恢复方法。

## 调试要点
- HardFault：保存异常栈帧与 CFSR/HFSR/MMFAR/BFAR，stacked PC 用匹配 ELF 做 addr2line；不要只复位继续测试。
- 栈/堆：启用栈水印/高水位统计，最大中断嵌套和 RTOS 任务栈都需余量。
- DMA：检查缓冲区生命周期、对齐、Cache（F7/H7）、双缓冲竞态和回调上下文。
- I2C：NACK/超时需记录寄存器与波形；处理总线锁死和外设复位，不无限阻塞。
- UART：长稳测试统计溢出、帧错误、噪声、环形缓冲高水位和丢包。
- FreeRTOS：核对中断优先级与 FromISR API、队列超时、任务看门狗和内存碎片。
- Flash：写/擦前确认电压与扇区，掉电安全和参数双备份/CRC 按需求测试。

## 量产与交付门禁
- 无未解释 HardFault、断言、看门狗复位或内存泄漏。
- 固件版本、硬件版本和验收报告一一对应。
- 编译无新增 warning，Flash/RAM 有余量，所有外设回归通过。
- 烧录/读保护/量产序列号方案由客户确认，智能体不自动设置不可逆选项字节。
